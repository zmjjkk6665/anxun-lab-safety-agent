# 演示视频分镜脚本（2-3 分钟）

> 目标：让评审在 90-180 秒内看懂「真实大模型驱动的实验室应急处置闭环」，
> 并看到 AGH 接入方式。录制工具：Windows **Win + G**（Xbox Game Bar）或 OBS，1080p / 30fps。

## 零、录制前必做（关键）

1. **先把 Key 注入环境变量再启动服务**，全程不要在屏幕上输入或显示 Key：

```powershell
$env:AGNES_API_KEY="你的Key"      # 赛事要求：Key 不得出现在演示材料中
python run.py web
```

2. 录屏范围选**浏览器窗口**（不要全屏，避免录到终端里的 Key）。
3. 清空旧产物，避免录到上一次的文件名：`Remove-Item outputs\traces\*, outputs\reports\*`
4. 关掉无关通知（微信/邮件弹窗）。
5. 备选方案：若真机触发限流（界面出现"降级"提示），改录 `mock` 模式——快且稳定（约 30 秒），
   真机证据改用 `outputs/traces/*.json` 与 `outputs/reports/*.md` 静态展示。

## 一、分镜（真机模式，总时长约 150 秒）

| 时间 | 画面动作 | 口播词（照读即可） |
|---|---|---|
| 0-15s | 打开大屏，缓慢平移展示：实验室平面图、12 台设备、三路探测器读数、右上角状态 | "这是'安巡'的实验室数字孪生大屏。平面上 12 台设备按 MHS 思路自描述：三路可燃气体探测器、摄像机、巡检机器人、电磁阀、机械臂、事故排风、声光报警、安全出口闸机。此刻浓度正常。" |
| 15-25s | 浓度爬升，S-01 变黄/橙/红，红色扩散圈出现；点击「启动应急处置」 | "4 秒后剧本注入乙炔泄漏。S-01 读数越过 200ppm 预警、500ppm 报警，系统触发应急处置任务，模型开始接管决策。" |
| 25-50s | 左侧时间轴逐步出现：读取探测器 → 调取 CAM-01 → 核查设备状态 | "第一步是多源感知。模型读取三路探测器，再调摄像机画面交叉验证——画面里检出烟雾、明火和 2 名在场人员，同时发现电磁阀执行器处于故障态。" |
| 50-80s | 时间轴出现：启动声光报警 → 广播疏散 → 解锁出口 | "注意这里：模型没有按脚本先关阀，而是因为画面里有人，把报警、广播疏散、解锁安全出口提到了最前面——人员安全优先，这是模型自主做出的判断。" |
| 80-105s | 时间轴：远程关阀 **失败**（红色）→ 机械臂就地手动关阀 **成功** | "远程关阀因执行器故障失败。工具返回失败被当作观测回灌给模型，模型自行改派机械臂 ARM-01 就地手动关阀——这是本作品的关键容错设计：不假设工具一定成功。" |
| 105-125s | 排风 100%、机器人前往气瓶间复测、浓度曲线下行 | "气源切断后启动事故排风到 100%，巡检机器人现场复测，浓度曲线持续下降。" |
| 125-145s | 探测器回落至绿色，报告面板弹出 | "三路探测器回到 2.5、10、0 ppm，低于 50ppm 安全线，处置闭环。这份事故报告——含根因分析和整改建议——是模型自己写的，不是模板填充。" |
| 145-160s | 切到 `outputs/traces` 的 JSON 与 `docs/AGH接入说明.md` | "每一步的思考、工具、入参、返回、耗时都进了 Trace，可回放可审计。工具层通过 MCP 暴露，AGH 可直接挂载；拿到 AGH 源码后切换模式，业务代码零改动。" |
