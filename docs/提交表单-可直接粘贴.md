## 四、作品详情（约 3000 字，直接复制下方全文）

```
作品名称：安巡 · 实验室安全应急处置 Agent
技术底座：Agnes Harness（AGH），模型使用组委会下发的 Agnes Key（亦支持替换其他 OpenAI 兼容模型）

一、背景与问题

高校与科研院所的化学实验室普遍存放乙炔、氢气、甲醇等易燃易爆介质，气瓶间与管路汇流排是泄漏高风险点。现行处置高度依赖人工：值班人员接到探测器报警后，需要到场确认、手动关阀、启动排风、组织疏散，每个环节都存在响应延迟；更关键的是，真实事故中常伴随设备失效——例如电磁阀电动执行器故障导致远程关阀不可用，此时若没有备选路径，处置流程会直接卡死。

与此同时，已有的"智能实验室"方案大多停留在监测告警层面，Agent 只能在屏幕上给出建议，无法真正完成"感知—判断—执行—复核"的闭环。其根因在于缺少一套能把模型决策与真实工具/设备执行可靠连接起来的运行时：模型负责判断下一步做什么，但谁来调用工具、谁来把执行结果回灌给模型、谁来记录全过程以便复盘，这些问题在传统 Agent 框架中往往被草率处理。

Agnes Harness（AGH）正是为解决这一层问题而开源的 Agent 执行基础设施：模型负责判断，Harness 负责调用工具、接收执行反馈并交回模型，循环推进直到任务结束。本作品的目标，就是把这套能力落到"科学与工程"的真实场景里——让 Agent 在实验室事故中真正动手处置，而不是只输出一段文字建议。

二、方案概述

作品名为「安巡」，是一个基于 Agnes Harness 的实验室安全应急处置 Agent。系统构建了有机合成实验室 B203 的数字孪生，内置 12 台设备：可燃气体探测器 3 台、摄像机 2 台、温湿度变送器、乙炔汇流排电磁阀、事故排风系统、巡检机器人、应急处置机械臂、声光报警器、安全出口闸机。全部为 MHS 模拟设备，无需任何实体硬件即可完整演示。

演练剧本为：气瓶间乙炔汇流排密封失效发生泄漏 → S-01 探测器报警触发处置任务 → Agent 按 SOP 完成确认、切断、控制、复核、报告。剧本中埋入了一个关键故障：VALVE-01 电磁阀的电动执行器无响应，远程关阀必然失败，用于验证 Agent 的容错与路径切换能力。

三、技术架构

系统分为五层：

1. 设备与仿真层：气体浓度按质量守恒式演化——"泄漏源项 − 一阶通风稀释（自然渗透 + 机械排风）− 自然沉降"，泄漏期间同样参与衰减，因此浓度存在稳态上限，不会随演练时长无限累积；任意点位浓度按距离指数衰减。独立线程推进仿真时钟，支持倍速调节。每台设备对外暴露统一的状态字典与能力清单，与 MHS 的设备自描述思路一致，可直接映射为 MHS 协议交互。
2. 工具层：14 个工具全部带 JSON Schema 描述，涵盖感知、移动、切断、通风、报警、疏散、观测、报告。工具返回值是模型唯一的观测来源，业务失败（如执行器无响应）明确返回 ok=false 与原因，绝不静默成功。
3. Harness 层：三通道可切换——AGH（MCP 接入 / CLI 下发）、内置 Agent Loop（与 AGH 同构）、离线规则规划器（基线对照与回归测试）。三者复用同一份工具注册表与 Trace 模型。
4. 模型层：OpenAI 兼容协议，默认接入组委会下发的 Agnes 模型 Key，亦可替换 base_url 与 model 接入其他模型；未配置 Key 或调用失败时自动降级，保证演示不中断。
5. 可观测与交付层：Trace 记录每一步的思考、工具、入参、返回、耗时；前端大屏实时渲染实验室态势、机器人轨迹、探测器读数与执行时间轴；处置结束后自动生成 Markdown 事故报告（结论 / 根因 / 时序 / 整改建议）。

四、AGH 的使用方式

作品在三个层面使用了 Agnes Harness 的能力：

- 核心任务的组织与执行：处置流程不是硬编码脚本，而是由 Harness 的 Agent Loop 以"模型决策 → 工具调用 → 反馈回灌"的方式逐步推进，模型依据上一步的真实返回值决定下一步。
- 工具调用：14 个设备工具通过 MCP 服务器（stdio + JSON-RPC 2.0，零第三方依赖）注册给 AGH，AGH 可直接拉起并编排；python run.py agh 会自动生成可直接加载的 AGH 配置文件。
- Skills 复用：本次验证过的处置规程沉淀为 AGH Skill，可跨实验室、跨项目复用，也可直接作为 system prompt 使用。

对于评审或离线环境，内置 Agent Loop 提供与 AGH 一致的循环语义，切换 AGH 时业务代码零改动。

五、处置流程与关键设计

完整执行链路：

1. 等待报警：监测到 S-01 达到预警/报警等级后触发任务，而非盲目巡检。
2. P1 感知：读取三路探测器与温湿度。
3. P2 确认：调取气瓶间摄像机画面交叉验证；派巡检机器人 R-01 前往泄漏源现场复测——单点报警不直接停机，避免误报代价。
4. P3 切断：远程关闭 VALVE-01 → 执行器无响应返回失败 → 自动改派机械臂 ARM-01 就地手动关阀，并有可达范围校验。这是本作品最具工程价值的一环：把"设备失效"作为一等公民纳入决策。
5. P4 控制：排风开至 100%、启动声光报警、机器人广播疏散指令、解锁全部安全出口。
6. P5 复核：持续采样浓度趋势，未降至安全阈值以下不允许结束。
7. P6 收尾：提交结构化事故报告。

关键设计取舍：

- 失败可见：工具业务失败会同时体现在返回值与 Trace 的 ok 标记上（初版曾因"调用未抛异常即算成功"掩盖失败，已修正），模型据此切换方案而非空转。
- 闭环才结束：强制以浓度达标作为终止条件，杜绝"动作做完即成功"的伪闭环。
- 可追溯：Trace 与报告同源，任何一次演练都可回放、可审计，对应 AGH Trace 页面的定位能力（区分是模型判断失误还是工具执行失败）。

六、验证结果

- 完整处置流程（离线规则规划器）：12 步执行完成，状态 completed。
- MCP 协议自检：initialize / tools/list / tools/call 全部通过。
- HTTP 服务：/api/state 返回 200，12 台设备状态正常。
- 端到端断言：阀门关闭、排风 100%、人员疏散、浓度降至安全阈值以下、报告生成，全部 PASS。
- 容错路径：注入执行器故障后，远程关阀失败自动切换机械臂手动关阀，闭环未被阻断。
- 真实模型联调：Agnes agnes-3.0-flash（端点 api.agnes-ai.cn/v1）驱动完整演练，13 步执行完成，状态 completed，耗时 85s，全程未降级（Trace 中无 `llm_fallback` 事件）。

演示视频（3 分 14 秒，1600×900，H.264，3.6 MB）由脚本驱动浏览器实录本次真机演练，画面叠加中文标题条、片头与复盘段，无需配音；与视频同源的真机 Trace 一并留存，可交叉核对。

七、创新点

1. 把设备失效纳入决策：不假设工具一定成功，失败即触发替代路径，贴近真实工程的容错要求。
2. 多源交叉确认：探测器 + 视频 + 机器人现场复测三点一致才判定真实泄漏，抑制误报停机。
3. 以达标为终止条件的处置闭环：把安全规程固化为可验收的机器约束，而非提示词里的软要求。
4. Harness 与业务解耦：同一份工具注册表服务 AGH、内置 Loop 与前端，接入 AGH 无需改业务代码。
5. 全过程可追溯：Trace 驱动的回放与自动报告，使 Agent 的每一次决策都可审计。
6. 零硬件门槛：MHS 模拟设备让方案可在任意环境复现，便于评审与推广。

八、应用前景

- 高校与科研院所实验室：作为安全应急值守 Agent，7×24 监测并在事故初期黄金时间自动处置。
- 化工与制药企业：接入真实 DCS/PLC 与巡检机器人后，可直接迁移同一套工具层与 SOP。
- 具身智能延伸：设备层已按 MHS 思路自描述，替换为真实设备（或 AGH 内置虚拟设备）即可把能力延伸到物理世界。
- 教学与演练：作为安全培训的虚拟演练平台，用 Trace 回放做复盘教学。

九、工程与合规

- 语言与依赖：Python 3.8+，零第三方依赖（标准库实现 HTTP 服务与 MCP 服务器），便于评审环境离线运行。
- 测试：提供 CLI / MCP / HTTP 三通道冒烟测试（python run.py selftest），全部通过。
- 模型 Key 合规：Key 只通过环境变量注入，代码与文档中无任何明文 Key；打包脚本内置密钥泄露扫描，命中即中止打包，演示视频中亦不出现 Key。
```

**2. 边界样例**

- 机械臂可达范围边界：`arm_manual_shutoff` 目标距离 > 3.0 m 时返回 `{"ok": false, "reason": "目标超出机械臂可达范围 (Xm > 3.0m)"}`，**拒绝执行而非静默成功**。
- 复核阶段边界：浓度趋势停滞（不再下降）或已达最大观测轮次 → 据实提交报告并提示人工介入，不允许无限等待。

**3. 失败样例**

- 设备失效：远程关阀执行器无响应 → 返回 `ok=false` → 自动改派机械臂 ARM-01 就地手动关阀，闭环未被阻断。
- 模型侧失败：Key 失效（401）/ 限流（429）/ 网络不可达 → 自动降级为内置规则规划器，处置闭环照常完成，CLI 打印「降级提示」。

三类样例分别对应 `tests/test_smoke.py` 的断言与「失败可见」设计，可用 `python run.py selftest` 一键复现。
