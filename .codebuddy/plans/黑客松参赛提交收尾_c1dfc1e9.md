## 核心功能（本轮交付）

1. **合规命名**：打包脚本改用赛事命名规则，产出 `本科生组-U126-大肥鱼脚香香-李家杰.zip`，不再使用时间戳命名。
2. **密钥泄露防护（关键）**：赛事明确要求 Key 不得出现在公开代码库、截图、演示材料中。打包前对将入包的每个文件做内容扫描，命中密钥特征即中止打包并定位文件，从流程上杜绝误提交。
3. **提交文案定稿**：作品简介（50 字内）、作品详情（约 3000 字）、提交检查清单、README 补入队伍/编号信息，并加入「无 Key 也能完整复现」说明（评审时 Key 可能过期）。
4. **复验不回归**：重新打包后校验文件名、体积、包内无密钥，并重跑冒烟测试确认功能未受影响。

## 硬性约束

- 严禁将 Agnes Key 写入任何文件（含 .env、README、docs、打包脚本、ZIP 内文件）；代码只从环境变量 `AGNES_API_KEY` 读取。
- 演示视频录制时不得暴露 Key（用环境变量设置，不要回显）。

## 技术栈

- 语言与依赖：Python 3.8+ **标准库**（`zipfile` / `os` / `re` / `argparse`），零第三方依赖，评审可离线运行
- 既有架构：统一入口 `run.py`（web / cli / mcp / agh / selftest），配置走 `config/default.json` + 环境变量覆盖

## 实施方案

采用「改造既有打包脚本 + 文案增量更新」的最小改动策略，不触碰已验证通过的仿真、工具与 Agent 层，控制回归风险。

**关键决策一：命名改为赛事规则，参数化可复用**
`scripts/package.py` 现有逻辑为 `安巡-参赛提交包-<时间戳>.zip`，`--name` 仅追加队伍名。改为按 `组别-参赛编号-队伍名称-队长姓名` 拼接，四个字段均由命令行参数提供（`--group/--code/--team/--leader`），默认值分别为 `本科生组 / U126 / 大肥鱼脚香香 / 李家杰`。参数化而非硬编码，便于后续改名或复用脚本。

**关键决策二：密钥扫描放在写入 ZIP 之前（失败即中止）**
扫描在 `zf.write()` 之前对每个待入包文件执行，命中即抛错退出、不生成 ZIP。相比"打包后再检查"，可避免残留半成品包被误上传。

- 检测规则（保守、避免误杀）：`sk-[A-Za-z0-9]{20,}`、`AGNES_API_KEY=<非空值>`、`api_key`/`apiKey` 后跟非空字符串值
- 跳过二进制与已排除文件；文本文件按 UTF-8 读取，解码失败则跳过（不误报）
- 命中时输出**文件名 + 行号 + 规则名**，不打印密钥原文（避免二次泄露）
- 退出码非 0，便于手工/CI 判断

**关键决策三：文案更新为增量修改**
仅在 `docs/作品简介.md` 追加队伍信息块、在 `docs/作品详情.md` 文首加队伍信息表与文末"评审复现说明"章节、在 `docs/提交检查清单.md` 回填表单字段与最终文件名、在 `README.md` 增加安全提示章节。不重写既有内容，避免丢失已打磨的正文。

## 执行要点（防回归）

- **不动业务代码**：`src/world.py`、`src/tools/`、`src/agent/`、`src/mcp/`、`src/server/` 本轮零改动，已验证的 13 步闭环不受影响。
- **扫描误杀处理**：`config/default.json` 中 `api_key` 为空字符串、`README.md` 示例里为占位符 `你的Key`，均不会被规则命中（规则要求值非空且 `sk-` 前缀长度 ≥20）；如遇误报应放宽规则而非删除文件。
- **热路径无关**：打包为一次性离线操作，扫描复杂度 O(包内文件总字节数)，包体约 0.07MB，毫秒级。
- **日志与输出**：仅打印文件名、行号、规则名与统计信息，绝不打印密钥内容。
